# Experiment 1 findings: the 7/9 case

The available pipeline reproduces the saved 7/9 result exactly on
`data/10ms_4s.dat`. Independent raw-event decoding shows that the two unsupported
windows contain substantial activity. The result is evidence against treating
7/9 statistical support as reliable synchronisation or as two missing flashes.

Start with the [aligned ON/OFF plot](../diagnostics/experiment_1_10ms/aligned_activity.png)
and the [generated evidence](../diagnostics/experiment_1_10ms/evidence.json).
[Reproduction instructions](experiment_1.md) describe the script and assumptions.

## What was verified

The raw interval is 8,470,450–9,615,000 µs after the first DAT event. Its
73,753,536 events were independently decoded with Prophesee's `PSEELoader`.
The resulting OFF/ON counts agree with the project decoder in **every 50 µs bin**.
Thus the following activity was recorded in the DAT and was not generated by
the detector's smoothing or scoring. This cross-check validates the two readers
against each other; it does not independently validate the camera clock.

The detector was rerun across the full retained recording, starting at
4,500,004 µs after the first event. It selected the same initial phase:
8,520,454 µs. All nine generated onset timestamps match the saved run. Timing
parameters, source hashes and existing source edits are captured with the output.
The detector and colour algorithm were left unchanged.

## Why “two missed flashes” is misleading

The labels below are the pipeline's assignments; their physical colour identity
has not been independently established.

| Model window | Raw ON | Raw OFF | Pipeline decision | Explanation |
|---|---:|---:|---|---|
| R1 | 338 | 314,163 | Supported | OFF-edge score 10.045 passes despite almost no ON response. |
| B1 | 879,637 | 6,642 | Unsupported | ON-contrast score −113.862; OFF-edge score −0.250. |
| B3 | 68 | 988,061 | Unsupported | ON-contrast score 1.633; OFF-edge score 2.077; both below 2.5. |

The B1 window has strong ON bursts. Its assumed late-dark interval contains
64,393 ON events in 400 µs. The detector extrapolates that dark rate to the
10 ms response interval, giving 1,609,825 background-equivalent events, more
than the 879,637 observed ON events. This produces a negative contrast score.
It is not a failure to load or see those events.

B3 is dominated by OFF activity, while the OFF test only examines a narrow
edge around the *predicted* illumination endpoint. High integrated OFF activity
does not ensure that this particular edge test passes.

The overall detector requires only six of the nine model windows to be
supported. Seven passing windows can therefore yield an automatic timing pass
despite these inconsistencies. It detects one phase and extrapolates eight more
windows; it does not independently measure nine LED onsets.

## Timing-model evidence

Over the selected raw interval, the log ON/OFF envelope has correlation **0.902**
at a **100 ms** lag. At the configured **31.5 ms** RGB cycle it is **−0.277**.
These are descriptive correlations at 500 µs envelope resolution, not confidence
probabilities or hardware timing measurements. The longer context plot shows
the repeating activity directly.

The evidence makes the assumed cycle and initial phase questionable. Moving
every window by a constant offset cannot change a 31.5 ms cycle into a 100 ms
cycle. However, a 100 ms event recurrence alone does not identify individual RGB
stages, their durations or the controller's dark intervals. No numeric replacement
timing is justified by this experiment alone.

## Implications for the project

Both parts of the proposed investigation matter: the raw recording contains
repeated bursts, and the pipeline can accept an interpretation whose light/dark
references are inconsistent with that activity. The raw events alone cannot
attribute those bursts uniquely to PWM, sensor behaviour or controller timing.
The experiment therefore does not settle a camera-versus-illumination hardware
diagnosis.

The next timing improvement should establish a validated schedule and reject
inconsistent schedules before extracting colour. Compare it with this preserved
baseline using an independent LED timing reference, then measure how timing
error changes per-cycle ROI colour vectors. Do not choose the timing that merely
makes the displayed colours look plausible.

No improved colour accuracy is claimed here. What is now available is a
reproducible baseline, raw evidence, and a concrete explanation for the two
unsupported windows.
